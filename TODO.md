# Бэклог технического долга

Задачи по [ревью MVP](REVIEW.md) в порядке приоритета. В первую очередь — защита от удаления другого рецепта и потери введённого текста.

| Приоритет | Задача | Как проверить |
| --- | --- | --- |
| Высокий | [R01. Исключить повтор ID рецепта](REVIEW.md#r01) | После удаления и создания рецепта старый адрес по-прежнему возвращает 404. |
| Высокий | [R06. Защитить черновик при сохранении](REVIEW.md#r06) | Ответ для А не стирает правки в Б. При ошибке введённый текст остаётся в форме. |
| Средний | [R05. Отбрасывать устаревший подбор](REVIEW.md#r05) | После смены продуктов запоздавший ответ не меняет список. |
| Средний | [R07. Отделить добавление продукта от обновления списка](REVIEW.md#r07) | После успешного добавления повторяется только запрос списка. |
| Средний | [R04. Исправить описание 422 в Swagger](REVIEW.md#r04) | И в схеме, и в ответе на пустой выбор поле `detail` имеет тип «строка». |
| Средний | [R02. Отбирать подходящие рецепты в SQL](REVIEW.md#r02) | На тех же демоданных по молоку загружаются два рецепта. Порядок, проценты и состав в ответе совпадают с MVP. |
| Средний | [R03. Передавать путь к базе целиком](REVIEW.md#r03) | Два имени, отличающиеся после `?`, создают отдельные базы. |
| Средний | [R08. Обработать текстовую ошибку сервера](REVIEW.md#r08) | При текстовом ответе 503 видно понятное сообщение, при 422 — пояснение из API. |
| Низкий | [R10. Проверить подбор через браузер](REVIEW.md#r10) | Тест нажимает кнопку и проверяет содержимое карточки. |
| Низкий | [R09. Исправить подпись при полном совпадении](REVIEW.md#r09) | Строка «Не хватает» появляется только при неполном совпадении. |
