# Бэклог технического долга

Открытые задачи по [ревью исходного MVP](REVIEW.md). Вверху стоят риски удаления записи, выбора неверного файла базы и потери введённых правок. Далее идут корректность подбора, обработка ошибок и работа с растущим каталогом. Последними идут улучшения тестов и текста интерфейса.

| Замечание | Приоритет | Задача | Как проверить исправление |
| --- | --- | --- | --- |
| [R01](REVIEW.md#r01) | Высокий | Исключить повтор ID рецепта после удаления. | Старый адрес возвращает 404 после создания нового рецепта. |
| [R03](REVIEW.md#r03) | Высокий | Исправить передачу пути к SQLite. | Два имени с разными суффиксами после `?` создают отдельные базы. |
| [R06](REVIEW.md#r06) | Высокий | Защитить форму при сохранении рецепта. | Успешное сохранение А не стирает правки в Б. При ошибке черновик доступен. |
| [R05](REVIEW.md#r05) | Средний | Отбрасывать устаревшие ответы подбора. | После смены выбора старый ответ не заполняет карточки. |
| [R07](REVIEW.md#r07) | Средний | Разделить подтверждение добавления и обновление справочника. | После ответа 201 при сбое чтения повторяется только GET. |
| [R04](REVIEW.md#r04) | Средний | Привести описание ответа 422 в Swagger в соответствие с API. | Тип поля `detail` одинаков в схеме и в фактическом ответе. |
| [R02](REVIEW.md#r02) | Средний | Отбирать кандидатов на подбор в SQL. | В примере с молоком загружаются только два подходящих рецепта. Состав, проценты и порядок результатов сохранены. |
| [R08](REVIEW.md#r08) | Средний | Обработать текстовое или пустое тело ошибки HTTP. | Пользователь видит понятное сообщение при 503 и описание ошибки при 422. |
| [R10](REVIEW.md#r10) | Низкий | Покрыть подбор браузерным тестом. | Тест проверяет результат после выбора продукта и нажатия кнопки. |
| [R09](REVIEW.md#r09) | Низкий | Уточнить подпись при полном совпадении. | Для полного совпадения показано «Все ингредиенты есть», для частичного перечислены недостающие продукты. |
