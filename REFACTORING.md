# Рефакторинг «Что приготовить?»

Сравнение исходного `mvp` (`b4d4f90`) с версией `aafd143`. Замечания и правила подсчёта взяты из [ревью](REVIEW.md) и [анализа MVP](ANALYSIS.md).

| Замечание | Было | Стало |
| --- | --- | --- |
| R01. ID рецепта | После удаления старый адрес мог указывать на новый рецепт. | SQLite сохраняет последовательность ID. При первом открытии базы MVP таблица обновляется в одной транзакции. Рецепты, их номера и связи с продуктами сохраняются. |
| R02. Подбор | Загружался весь каталог. | SQL отбирает рецепты хотя бы с одним совпадением. У кандидатов загружается полный состав для расчёта процента. |
| R03. Путь к SQLite | Вопросительный знак обрезал имя файла базы. | Путь передаётся в `URL.create` отдельным полем. |
| R04. Ответ 422 | Swagger описывал массив, API возвращал строку. | В схеме ответа `detail` указан как строка. |
| R05. Смена выбора | Запоздавший ответ возвращал рецепты для прежнего выбора. | Форма проверяет номер запроса перед выводом. |
| R06. Черновик | Ответ на сохранение мог очистить другой открытый рецепт. | Во время сохранения редактор и карточки временно заблокированы. При ошибке текст остаётся в форме. |
| R07. Добавление продукта | После успешной записи сбой чтения списка приводил к повторной отправке продукта. | Поле очищается после записи. Кнопка «Обновить список» повторяет только чтение. |
| R08. Ошибка сервера | При текстовом ответе 503 пользователь видел ошибку разбора JSON. | Форма показывает понятный текст и код HTTP. |
| R09. Полное совпадение | Карточка показывала «Не хватает: всё есть». | Когда все продукты выбраны, карточка пишет «Все ингредиенты есть». |
| R10. Интерфейс | Тесты обращались к API напрямую. | Пять сценариев в Chrome проверяют подбор, смену выбора, редактор и обработку ошибок. |

## Метрики

| Показатель | MVP | После |
| --- | ---: | ---: |
| Сложность Python, средняя / максимум | 2,33 / 9 | 2,32 / 9 |
| Сложность JavaScript, средняя / максимум | 2,00 / 8 | 2,00 / 9 |
| Связность классов H | 5 / 8 = 0,625 | 5 / 9 = 0,556 |
| Известные дефекты на 1 000 строк | 8 / 0,463 = 17,3 | 0 / 0,625 = 0 |
| Покрытие строк Python | 217 / 222 = 97,75% | 236 / 241 = 97,93% |
| Покрытие алгоритма подбора | 17 / 17 = 100% | 17 / 17 = 100% |

В JavaScript добавилась обработка ответа с пустым или текстовым телом. Максимум сложности вырос на единицу. У моделей осталось четыре внутренние связи, а класс ответа 422 увеличил число классов до девяти. Плотность рассчитана по восьми исходным дефектам из ревью. R02 и R10 учитывались отдельно.

## Проверка подбора

На обеих версиях использовался одинаковый каталог из 1 000 рецептов. Молоко входило в два рецепта, у одного из них также была соль. Для запроса по молоку MVP загрузил 1 000 объектов рецептов, после изменения — два. Ответы API совпали побайтно, включая порядок, состав и проценты.

После трёх прогревочных запросов выполнено ещё 15 на каждой версии через FastAPI TestClient с локальной SQLite. Медиана снизилась с **18,16 до 2,21 мс**. Время относится к этому каталогу и машине.
