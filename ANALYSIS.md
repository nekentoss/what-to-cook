## Что стоит исправить в первую очередь

1. **Высокий приоритет — потеря записи или черновика.** SQLite может присвоить новому рецепту ID ранее удалённого. Кнопка из старой вкладки тогда удалит другой рецепт. В редакторе можно открыть рецепт Б, пока сохраняется А. Когда придёт ответ для А, он сотрёт черновик Б. Сначала нужны стабильные ID и защита формы на время сохранения. [R01](REVIEW.md#r01) · [R06](REVIEW.md#r06)
2. **Средний приоритет — лишнее чтение при подборе.** Сложность обработчика `get_matches` всего 2, но запрос загружает весь каталог. На штатной демобазе запрос по молоку прочитал шесть рецептов и вернул два. Стоит отбирать кандидатов в SQL и загружать их полный состав. При повторной проверке сравнить число загруженных рецептов на тех же данных, сохранив проценты, порядок и список недостающих продуктов. [R02](REVIEW.md#r02)
3. **Средний приоритет — обработка ошибок.** Функция `api()` в JavaScript имеет сложность 8. Она отправляет запрос, разбирает ответ и готовит текст ошибки. Текстовый ответ 503 обрабатывается как JSON, и пользователь видит сообщение парсера. Внутри функции `create_app` (строки 39–147) описание маршрутов и обработка ошибок заданы отдельно. Для ответа 422 Swagger указывает массив, а сервер возвращает строку. Следует согласовать тип ответа в документации и проверить отображение обеих ошибок. [R08](REVIEW.md#r08) · [R04](REVIEW.md#r04)
4. **Низкий приоритет — проверка интерфейса.** Порог задания в 60% выполнен для расчёта совпадений. При этом ни один из 42 тестов не нажимает кнопку подбора. Один браузерный тест с выбором продукта проверит путь от кнопки до карточки рецепта. Остальные задачи и их приоритеты перечислены в бэклоге. [R10](REVIEW.md#r10) · [Бэклог](TODO.md)

## Как получены числа

**Сложность.** Python проверен Lizard 1.17.10, JavaScript — правилом `complexity` ESLint 9.39.1. В Python сумма оценок равна 49, в JavaScript — 48. Максимум в Python у `match_recipes` (9), далее идёт `seed_database` (8). Функция подбора выделена из HTTP и базы и проверяется отдельно. В ней важнее сохранить правила сортировки и расчёта, чем уменьшить число ветвлений само по себе. [Расчёт совпадений](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/matching.py#L4-L28)

**Связность.** Для пакета `app` использована формула Relational Cohesion (H). Прямая связь засчитывалась один раз для каждой пары «класс использует класс» через наследование, поле или ORM-связь. Получились пары `Recipe → Product`, `RecipeRead → ProductRead`, `MatchRead → RecipeRead` и `MatchRead → ProductRead`. Показатель описывает модели и схемы. Обработчики HTTP в этом проекте написаны функциями и в H не входят. [Модели](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/models.py#L15-L30) · [Схемы](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/schemas.py#L9-L55) · [Формула H](https://www.ndepend.com/docs/code-metrics)

**Плотность дефектов.** В числителе восемь замечаний о неверном поведении (R01 и R03–R09). Сюда включена и противоречивая подпись при полном совпадении (R09). R02 относится к расходу ресурсов, R10 — к пробелу в тестах. Знаменатель — число строк кода Python и JavaScript по Lizard, без тестов, HTML и CSS. Для сравнения после исправлений нужно применить те же правила подсчёта. [Ревью](REVIEW.md)

**Покрытие.** Учитывались исполняемые строки Python. Все пять пропущенных строк относятся к запуску команды заполнения базы в `seed.py`. Эти проценты не характеризуют работу JavaScript в браузере. [Команда заполнения](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/seed.py#L62-L68)

Команды для повторного замера из корня проверяемой версии. Для Python нужны зависимости из `requirements-dev.txt`, для JavaScript — команда `npx`.

```bash
python -m pip install lizard==1.17.10
python -m lizard -l python -l javascript app
npx --yes --package=eslint@9.39.1 eslint --no-config-lookup --rule 'complexity: [warn, 0]' app/static/app.js
python -m pytest tests/test_matching.py --cov=app.matching --cov-report=term-missing
python -m pytest --cov=app --cov-report=term-missing --cov-report=json
```

Порог `0` у ESLint выводит оценку каждой функции для замера. В этом отчёте значения JavaScript берутся из ESLint, а число строк обоих языков — из Lizard.
