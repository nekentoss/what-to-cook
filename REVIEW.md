Исходная версия — `mvp`, коммит `b4d4f90`. При разборе использовался Codex. Порядок исправлений указан в [бэклоге](TODO.md).

## Критические

<a name="r01"></a>

### R01. Из старой вкладки можно удалить новый рецепт

SQLite может повторно выдать ID удалённого рецепта, если его номер был наибольшим. При проверке два рецепта последовательно получили ID 7. Старая карточка показывает название первого, но кнопка удаления отправляет только ID. При таком совпадении нажатие «Удалить» в старой вкладке удалит второй рецепт. [Модель рецепта](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/models.py#L24-L30) · [Кнопка удаления](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/static/app.js#L102-L109)

Включить SQLite `AUTOINCREMENT` для рецептов. При обновлении существующей таблицы сохранить ID и связи с ингредиентами.

## Важные

<a name="r02"></a>

### R02. Подбор читает все рецепты

На демоданных сервер загрузил из базы все шесть рецептов вместе с ингредиентами. Для запроса по молоку подошли только «Омлет» и «Блины». Даже добавление рецепта без молока увеличивает объём работы для этого запроса. [Запрос к базе](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/main.py#L139-L145) · [Расчёт совпадений](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/matching.py#L11-L17)

Отбирать в SQL рецепты, где есть хотя бы один выбранный продукт. Для них загружать полный состав, иначе изменятся процент совпадения и список недостающих ингредиентов.

<a name="r03"></a>

### R03. Вопросительный знак в пути меняет имя базы

При пути `ужин?пятница.db` приложение создало файл `ужин`. Причина в том, что путь вставляется в URL подключения и `?` обозначает начало параметров. Два разных имени с общим началом могут привести к одному файлу. [Подключение к SQLite](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/database.py#L13-L18)

Передавать путь в `URL.create("sqlite", database=...)`. При проверке с этим способом подключения имя файла сохранилось целиком.

<a name="r04"></a>

### R04. Формат ошибки 422 расходится с документацией API

Для `POST /api/matches` Swagger описывает поле `detail` как массив. При пустом выборе API возвращает в нём строку. Клиент, написанный по документации, получит другой тип данных. [Обработчик ошибок](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/main.py#L55-L79) · [Маршрут подбора](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/main.py#L139-L141)

Указать в OpenAPI модель ответа 422 со строковым `detail` для маршрутов, которые возвращают такой ответ.

<a name="r05"></a>

### R05. После смены продуктов появляются прежние результаты

Если выбрать молоко, запустить подбор и снять флажок до ответа сервера, список сначала очистится. Когда ответ придёт, в списке снова появятся рецепты для молока. [Вывод результатов](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/static/app.js#L163-L176) · [Смена выбора](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/static/app.js#L179-L182)

Присваивать запросу номер. При изменении выбора или очистке результатов увеличивать номер и выводить ответ только при совпадении с текущим.

<a name="r06"></a>

### R06. Сохранение одного рецепта стирает правки в другом

Пока сохраняется рецепт А, можно открыть рецепт Б и начать его редактировать. Когда сервер подтвердит сохранение А, `resetEditor()` очистит уже открытую форму Б. [Открытие формы](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/static/app.js#L90-L101) · [Сброс после сохранения](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/static/app.js#L147-L159)

На время сохранения блокировать поля, отмену и переход к другому рецепту. При ошибке снова разрешать редактирование и сохранять введённый текст в форме.

<a name="r07"></a>

### R07. Продукт уже добавлен, а форма сообщает об ошибке

После записи продукта форма запрашивает обновлённый список. Если этот запрос сорвётся, название останется в поле, а пользователь увидит ошибку связи. Повторное нажатие «Добавить» вернёт 409, потому что продукт уже существует. [Форма добавления продукта](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/static/app.js#L134-L144)

После ответа 201 очистить поле и подтвердить добавление. Если список загрузить не удалось, предложить повторить только его загрузку.

<a name="r08"></a>

### R08. При ответе 503 пользователь может увидеть ошибку разбора JSON

Интерфейс пытается прочитать любую HTTP-ошибку как JSON. Если сервер вернёт 503 с обычным текстом, на экране появится техническое сообщение о разборе ответа. [Чтение ответа](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/static/app.js#L17-L24) · [Вывод ошибки](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/static/app.js#L122-L131)

Показывать `detail`, когда удалось получить строку из JSON. Для пустого или текстового ответа выводить понятное сообщение с кодом HTTP.

## Рекомендательные

<a name="r09"></a>

### R09. При полном совпадении карточка пишет «Не хватает: всё есть»

Подпись «Не хватает» добавляется даже к пустому списку. Для полного совпадения выводить «Все ингредиенты есть», а для частичного перечислять недостающие продукты. [Текст карточки](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/app/static/app.js#L170-L176)

<a name="r10"></a>

### R10. Автотесты обходят кнопку подбора

Тест страницы проверяет загрузку файла JavaScript, а тест API отправляет запрос напрямую. Оба могут пройти, даже если кнопка «Подобрать рецепты» перестанет работать. [Тест страницы](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/tests/test_api.py#L4-L10) · [Тест API](https://github.com/nekentoss/what-to-cook/blob/b4d4f90f1a47c4327be4111d1e7a94d44a94069c/tests/test_api.py#L108-L121)

Добавить браузерный тест на временной базе. Выбрать молоко, нажать кнопку и проверить название рецепта, процент совпадения и список недостающих продуктов.
