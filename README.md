# Что приготовить?

Учебное веб-приложение подбирает рецепты по продуктам, которые есть дома. Это **этап 1 и исходный AI-сгенерированный MVP**. Техническое задание: [SPEC.md](SPEC.md). Использование Codex и выполненные проверки: [AI_USAGE.md](AI_USAGE.md).

Можно добавлять продукты, создавать, просматривать, изменять и удалять рецепты. Подбор показывает процент совпадения, имеющиеся и недостающие ингредиенты. Все операции доступны через русский интерфейс и API. Демонстрационные данные: 15 продуктов и 6 рецептов.

Стек: Python **3.9.6**, FastAPI 0.128.8, SQLAlchemy 2.0.55 с синхронными сессиями, SQLite, HTML/CSS/JavaScript без frontend-фреймворков. Начальные тесты: pytest и pytest-cov. Версии установленных библиотек и их зависимостей закреплены в `requirements.txt` и `requirements-dev.txt`.

## Локальный запуск на macOS

Откройте терминал в папке проекта. При подготовке использован системный `python3` версии 3.9.6; Dockerfile использует ту же версию. Зависимости устанавливаются только в `.venv`.

```bash
cd /Users/nico/vscode/FinalTaskCR
python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip==26.0.1
python -m pip install -r requirements-dev.txt
python -m app.seed
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Если `.venv` уже создано, достаточно активировать его. Для установки пакетов нужен доступ к PyPI. Для запуска без тестовых инструментов можно установить только `requirements.txt`.

- Приложение: <http://127.0.0.1:8000>.
- Swagger: <http://127.0.0.1:8000/docs>.
- Схема API: <http://127.0.0.1:8000/openapi.json>.
- Остановка сервера: `Ctrl+C`.

По умолчанию база хранится в `data/recipes.db`, каталог создаётся автоматически. Другой путь задаётся через `DATABASE_PATH` до запуска соответствующей команды:

```bash
export DATABASE_PATH="$PWD/data/another.db"
python -m app.seed
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Пустая база создаётся при старте приложения; демоданные автоматически не добавляются. Команду `python -m app.seed` можно повторять: существующие продукты и рецепты определяются по названию без регистра и пробелов по краям и пропускаются. Пользовательские данные не удаляются и не перезаписываются. Если пользовательский рецепт совпал по названию с демонстрационным, он сохраняется как есть.

## Тесты

В отдельном терминале из корня проекта:

```bash
source .venv/bin/activate
python -m pytest
```

Только расчёт совпадений, без HTTP и базы:

```bash
python -m pytest tests/test_matching.py
```

API-тесты создают отдельную временную SQLite для каждого теста. Пользовательская база не используется. На этапе 1 отчёт по покрытию не строится; pytest-cov установлен для следующих этапов.

## Docker Compose

Нужен установленный и запущенный Docker Desktop для macOS с Compose. Если локальный сервер занял порт 8000, сначала остановите его.

```bash
docker compose up --build
```

В другом терминале заполните базу контейнера:

```bash
docker compose exec web python -m app.seed
```

Адреса приложения и Swagger те же. В контейнере Uvicorn слушает `0.0.0.0:8000`; порт компьютера опубликован на `127.0.0.1:8000`. SQLite находится в `/app/data/recipes.db` и сохраняется в именованном томе `recipe-data` при пересоздании контейнера. Локальная база и база контейнера независимы.

```bash
docker compose down
docker compose up --build
```

Эти команды сохраняют том. Для проверки сохранности после повторного запуска откройте приложение и убедитесь, что добавленные записи остались.

На машине подготовки Docker отсутствовал. Проверены синтаксис YAML, настройка порта и наличие именованного тома; сборка образа, запуск Compose и сохранение данных при пересоздании контейнера пока **не проверены**.

## Правила API

| Метод и путь | Действие |
| --- | --- |
| `GET /api/products` | Список продуктов |
| `POST /api/products` | Добавить продукт: `{"name":"Яйцо"}` |
| `GET /api/recipes` | Список рецептов |
| `GET /api/recipes/{id}` | Получить рецепт |
| `POST /api/recipes` | Создать рецепт |
| `PUT /api/recipes/{id}` | Полностью изменить рецепт |
| `DELETE /api/recipes/{id}` | Удалить рецепт, сохранив продукты |
| `POST /api/matches` | Подбор: `{"product_ids":[1,2]}` |

Тело создания и изменения рецепта: `{"name":"Омлет","instructions":"Приготовить.","ingredient_ids":[1,2]}`. ID продуктов должны существовать; повтор в составе рецепта запрещён. Повторы в выборе для подбора разрешены и считаются один раз.

Процент равен числу имеющихся ингредиентов рецепта, делённому на число всех его ингредиентов, умноженному на 100. Вес и количество не учитываются. Рецепты без совпадений исключаются. Сортировка выполняется по точной доле по убыванию, затем по названию в порядке Unicode и ID. Процент отображается с одним знаком после запятой.

Некорректные данные возвращают 422 с русским текстом в `detail`, дубли продуктов - 409, отсутствующий рецепт - 404. Названия очищаются от пробелов по краям; регистр в названиях продуктов не влияет на уникальность. Отсутствие совпадений возвращает `200` и `[]`.

## Структура

```text
app/
  main.py         # FastAPI, маршруты и обработка ошибок
  database.py     # путь SQLite, внешние ключи, сессии
  models.py       # продукты, рецепты и таблица связи
  schemas.py      # входные и выходные данные API
  matching.py     # расчёт без HTTP и базы
  seed.py         # отдельное демозаполнение
  static/         # HTML, CSS, JavaScript
tests/            # начальные unit- и API-тесты
data/             # локальная SQLite, не входит в Git
```

## Git и первый Pull Request

`main` содержит начальный пустой коммит. Ветка `mvp` содержит исходную версию этапа 1 и после финальной фиксации должна сохраняться без изменений. Финальный хеш можно получить командой `git rev-parse mvp`. Автор локальных коммитов: `nekentoss`; email оставлен пустым по указанию пользователя.

Удалённый репозиторий ещё не создавался, код не публиковался. Когда решите опубликовать проект, выполните из этой папки (GitHub CLI уже установлен):

```bash
gh auth login
gh repo create what-to-cook --private --source=. --remote=origin
git push -u origin main
git push -u origin mvp
gh repo edit --default-branch main
gh pr create --base main --head mvp --title "Этап 1: исходный MVP" --body "ТЗ, FastAPI-приложение, русский интерфейс, начальные тесты и Docker. Выполненные проверки описаны в AI_USAGE.md; Docker ещё не проверен."
```

Эта последовательность создаёт приватный репозиторий; имя `what-to-cook` должно быть свободно в вашем аккаунте. Первый код приложения попадёт в `main` только после объединения настоящего PR на GitHub. Локально `mvp` в `main` не вливайте. При объединении не удаляйте ветку `mvp`.

Code review, метрики, CI, pre-commit и последующий рефакторинг относятся к следующим этапам и здесь не выполнялись.
