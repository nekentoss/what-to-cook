# Техническое задание: «Что приготовить?»

## Назначение

Учебное веб-приложение помогает выбрать рецепт по имеющимся продуктам. Этап 1 включает исходный AI-сгенерированный MVP, документацию и начальные тесты.

## Технологии

Python 3.9.6, FastAPI, синхронный SQLAlchemy, SQLite, HTML, CSS и обычный JavaScript. Интерфейс и API работают с одного адреса; Swagger доступен по `/docs`. Тесты используют pytest, установлен pytest-cov. Для контейнерного запуска предусмотрены Dockerfile и Compose.

## Функции

- Общий справочник продуктов: просмотр и добавление.
- Рецепты: список, отдельный просмотр, создание, полное редактирование и удаление.
- Рецепт содержит ID, название, инструкцию и ингредиенты из справочника. Связь рецептов и продуктов хранится в отдельной таблице многие-ко-многим.
- Подбор по выбранным продуктам: процент совпадения, имеющиеся и недостающие ингредиенты.
- Все операции доступны в русском веб-интерфейсе. Удаление требует подтверждения; ошибки API отображаются текстом.
- Отдельная команда добавляет 15 демонстрационных продуктов и 6 рецептов в пустую базу.

## Бизнес-правила

- Названия и инструкции очищаются от пробелов по краям и не могут быть пустыми. Названия продуктов сравниваются после `strip()` и `casefold()`, поэтому `Молоко` и ` молоко ` считаются дублями. Внутренние пробелы сохраняются.
- Рецепту нужен хотя бы один ингредиент. Повторы ингредиентов и неизвестные ID продуктов отклоняются. Одинаковые названия рецептов допустимы.
- Неизвестный рецепт возвращает 404. Удаление рецепта сохраняет справочник продуктов.
- Процент = число выбранных ингредиентов рецепта / число всех ингредиентов рецепта × 100%. Вес и количество не учитываются; повтор выбранного ID не увеличивает совпадение.
- Результаты без совпадений исключаются. Сортировка: точная доля по убыванию, затем название в порядке Unicode, затем ID по возрастанию. Округление до одного десятичного знака используется только для вывода.
- Пустой выбор и неизвестные ID возвращают понятную ошибку 422. Отсутствие подходящих рецептов возвращает пустой список и сообщение в интерфейсе. Дубли продукта возвращают 409.

## Ограничения

Один пользовательский справочник, без авторизации, миграций, учёта порций, редактирования продуктов и внешних сервисов. База по умолчанию: `data/recipes.db`; путь меняется через `DATABASE_PATH`. Сессии закрываются после запросов, внешние ключи SQLite включены. Демоданные добавляются вручную; повторный запуск пропускает существующие названия и не меняет пользовательские записи. В контейнере SQLite сохраняется в именованном томе.

## Критерии приёмки

1. Приложение запускается локально, интерфейс открывается по `/`, документация - по `/docs`.
2. Через интерфейс можно добавить продукт, создать, прочитать, изменить и удалить рецепт, выполнить подбор и увидеть ошибки ввода. Пользовательский текст не интерпретируется как HTML.
3. API соблюдает перечисленные правила, включая проверку ссылок и сортировку до округления. Расчёт совпадений тестируется без HTTP и базы.
4. Начальные unit- и API-тесты проходят; API-тесты используют отдельную временную SQLite. Повторное заполнение не создаёт дубли и не изменяет пользовательские данные.
5. README содержит команды macOS, тестов и Docker. Исходный MVP сохранён в `mvp`; `main` содержит только начальный пустой коммит до первого PR. Недоступные проверки явно перечислены в документации.
